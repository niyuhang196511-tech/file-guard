# FileGuard 文件变更监控与版本追溯

当前迭代版本为 **1.23.0**。本项目包含 Windows 桌面应用源码、离线 Vue 中文界面、文件监控与解析引擎、数据库结构、构建脚本和回归测试。当前交付为开发版。Windows 安装包与便携程序需要在 Windows x64 构建机生成。

## 1.23.0 Windows 采集修复与扫描诊断

Windows 文件采集和完整保存核对可正确处理路径与读取句柄返回的时间差异。仅改变文件名大小写时，扫描可沿用同一文件的历史。历史恢复在持有写入保护时原子替换目标，已有读取句柄仍可读完原内容。目标文件系统需要支持 Windows 的受保护替换操作。

在「目录监控 → 扫描运行记录」按日期、结果、触发来源、异常类别或跳过原因筛查，查看整组命中的读取量、等待与跳过次数，以及 P50、P95 耗时。可跨页选择两次扫描，按扫描先后比较指标，或按已应用的条件导出含扫描编号和跳过明细的 CSV。

从运行记录可打开「当前等待队列」，按原因、最近观察时间或尝试次数找出待处理文件。历史运行记录每目录保留最近 200 次，汇总覆盖当前筛选命中的记录。离线预览可用仓库台账目录体验对照与等待原因筛选。Windows 与 Linux 都能识别分号 CSV 中带引号的多行单元格。详见 [100 项优化与验收清单](docs/1.23迭代设计.md)。

## 1.22.0 历史原件预览

从版本时间线、版本对比或历史正文命中打开所选原件。校验大小与 SHA-256 后，可按物理行查看文本，或按字节偏移查看十六进制和 ASCII。支持关键词检索、范围定位、切换同一文件的版本及导出 CSV。

离线预览提供退货台账文本和历史工作簿字节两个入口。详见 [100 项优化与验收清单](docs/1.22迭代设计.md)。

## 1.21.0 清单三方对照

在同一监控目录选择一份较早清单作为基准，再选择两份后续清单。可区分单侧变动、两侧一致、互补变化和冲突，也会提示不同文件身份的候选路径争用。支持查看三侧历史版本、拿两个版本对比及导出 CSV。

离线预览在仓库台账目录提供了月初、月中和月末样例。搜索「退货轨迹」可查看正文在月中变化、月末回到基准的情况。详见 [100 项优化与验收清单](docs/1.21迭代设计.md)。

## 1.20.0 路径沿革

打开「路径沿革」，按完整相对路径、子目录或文件身份查看已采集的可见事件。原路径和事件路径均可匹配，便于区分移入、移出、删除以及同名文件重新建档。可跟踪单个身份、查看原事件或导出当前范围的 CSV。

离线预览可点击「查示例旧文件名」，查看「仓库交接.md」改名的记录。详见 [100 项优化与验收清单](docs/1.20迭代设计.md)。

## 1.19.0 历史版本交付篮

从「历史版本」或「版本对比」将指定版本加入交付篮，可跨文件和目录选择，同一文件也可交付多个保存版本。打开交付篮可预检归档、导出明细 CSV 或生成 ZIP。接收方可用「核查交付包」校验包内的文件摘要，保留原选择的一方还可以按篮核对漏交、多交和错版。

离线预览可加载三版本示例，下载真实 ZIP 并体验参考核查。详见 [100 项优化与验收清单](docs/1.19迭代设计.md)。

## 1.18.0 批量版本复核

在「复核工作台」跨页勾选需要处理的版本，每批最多 100 个。点击「批量复核」，可统一复核结论，或保留、替换、追加各版本备注。先比较预览中的当前值与拟写入值，再确认整批。若有其他会话更新了其中任何一条复核记录，整批暂停，核对新意见后可重新预览。

提交成功后可从回执打开对应审计，查看批次说明和各版本修改前后的结论与备注。详见 [100 项优化与验收清单](docs/1.18迭代设计.md)。

## 1.17.0 逐行来源

在「历史版本」选择一个文本版本的「逐行来源」，可沿相邻历史快照追溯每行的来源版本和原行号。可按来源、关键词和行号筛查，打开对应版、与目标比较或导出 CSV。遇到旧快照无法读取或超过追溯深度时，页面会区分已确认的行和只能追到最早可见版本的行。

离线预览中点击「查看示例退货台账」，可比较 V3 中保持不变的表头和改回原数量的正文分别来自哪次保存。详见 [100 项优化与验收清单](docs/1.17迭代设计.md)。

## 1.16.0 相同内容追溯

打开「相同内容追溯」，按 SHA-256 找出正文完全相同的跨文件副本或同一文件回到旧正文的版本。可按监控目录、最近登记路径、保存日期和文件状态缩小范围，再打开某组的全部引用，查看复用字节、打开具体版本、校验归档副本或导出 CSV。

离线预览点击「查看示例交接副本」，可核对两个目录中的交接文件如何引用同一份正文。详见 [100 项优化与验收清单](docs/1.16迭代设计.md)。

## 1.15.0 历史正文检索

打开「历史正文检索」，输入记得的字词、业务编号或整行文本，查找 TXT、Markdown、CSV、TSV、日志以及常见源码和配置文件的已保存版本。可切换到全部历史版本，按目录、日期、后缀、关注状态或已删除等条件缩小范围。检索结果显示行号、起始列和上下文，可打开命中版本、与上版比较或导出本批命中片段。

离线预览中点击「查找示例 RK-001」，即可查看包含该编号的历史文本。详见 [100 项优化与验收清单](docs/1.15迭代设计.md)。

## 1.14.0 保存核对、跨文件台账对账与字段体检

在「历史版本 → 保存核对」查看该文件最近的在册版本、现场大小和当前采集状态。快速核对只看大小，可以每五秒刷新一次。完整核对读取磁盘文件并比较 SHA-256，可分清与最新版相同、改回旧版和已落盘但尚未入库三种情况。需要核实历史正文是否仍可用时，勾选“同时校验在册历史副本”。文件可保持打开；编辑器尚未保存的草稿无法读取。

在「历史版本 → 台账对账」选择两份 Excel、CSV 或 TSV 历史台账，各自指定版本、工作表、表头行和一至三个编号列。按编号查看单侧记录、调序和字段变化。重复或不完整编号单列，由用户回原表核实。可按字段查看影响范围，检查数值容差所忽略的原始差别，或在“字段体检”中查看空值、数值范围与取值频次。比较规则可命名保存，后续月度台账可按相同表头布局重新应用。

离线样例包含「计划领料.xlsx」及「领料回执.tsv」。两侧选 V2，以“物料编号＋批号”对账，允许跨文本与数值类型进行十进制比较，可找出 A-01 / L1 从计划 80 件变成实发 78 件。详见 [100 项优化与验收清单](docs/1.14迭代设计.md)。

## 1.13.0 期间对照与字段变动轨迹

在「变更记录 → 变更期间对照」选择本期起止日期，系统自动取紧邻上期的相同天数。可以按文件、目录、文件夹、后缀、类型、来源、星期或小时汇总，按次数增减找出两期变化最大的组，再打开该组最近事件。撤回或移出普通日志的事件会从两期查询和导出中排除。

在「历史版本 → 字段变动轨迹」输入业务编号、字段或位置。打开离线示例中的「退货轨迹.csv」，输入 RK-001，即可查看数量从 100 到 120 再到 100 的两次保存。「数值差异核对 → 追踪此项」可直接带入字段和编号。满足唯一编号条件的 Excel 台账整批重排后，明细现在能同时呈现行序和真实内容修改。

本版增加 VCF 联系人、ICS 日历、GeoJSON 地理要素、WebVTT 字幕、RIFF/WAV 音频和未压缩 TAR 归档的结构对比。文本类新格式可切回原文。旧仓库第一次升级会把上述格式及 Excel 的相邻版本放入后台重新解析队列，原始历史对象保持原样。查看 [100 项优化与验收清单](docs/1.13迭代设计.md)。

## 1.12.0 历史交付与数值核对

在「目录清单」选择一份历史清单，再打开「查看目标清单成员与交付」。例如选择月末清单并筛选 xlsx 后，桌面版可导出当时的工作簿，即使原文件后来改名、更新或删除。接收方可从「系统设置 → 核查交付包」核实内容是否符合包内清单。持有原清单的用户还可从清单页面核查是否少交、超选或错版。现场核对可选择快速比大小或完整比内容。

在 Excel、CSV 或 TSV 的「版本对比」中打开「数值差异核对」，可按业务编号、字段、升降方向或差额筛选，点击位置返回原差异。变化率取差额除以旧值的绝对值，旧值为零时只显示差额。汇总只包括符合条件的变化项。

从「历史版本」恢复前，先核对磁盘内容与历史副本。预览后如果文件又被保存，请重新预览。系统设置中的「仓库体检报告」保留最近五次完整检查，可找出异常对象引用的各个版本。「核查已有备份」同时给出本机独有内容及尚未覆盖的版本数。

离线预览支持下载整份示例清单的历史交付包。对自有文件按条件打包和新建体检报告使用桌面开发版。详见 [本轮 100 项优化与验收清单](docs/1.12迭代设计.md)。

## 1.11.0 跨文件检索与采集诊断

打开“差异检索”，可查已解析的相邻版本事件。例如把路径设为“库存台账”、数值方向设为“数值下降”，查询后点“核对原差异”可直接查看对应工作表与位置。保存常用条件后，下一次打开可直接应用。检索与导出遵循普通事件的可见范围。

“目录监控 → 监听采集策略”可为各目录设置稳定等待时长。默认仍为 1.5 秒，可以选择对所有文件类型生效。“等待队列”显示正在等待的文件和原因。“扫描运行记录”保留每个目录最近 200 次扫描。编辑器内未保存的变化须先落盘，连续保存期间可能合并中间状态。

Excel 整表搜索可以跨行页和列页定位。对比还能识别图片、图表及 VBA 项目摘要。新增 EML、EPUB 和 GPX 比较。开发版的 100 项增量、验证口径和适用边界见 [本轮清单](docs/1.11迭代设计.md)。

## 1.10.0 目录交接、日志可见范围与后台状态

在“目录清单”保存扫描所得的文件清单，用两份清单核对交接前后的路径、版本与字节变化。Excel 整行对比可筛选内容、格式、批注、链接或增删调序。INI、TOML、SRT、IPYNB 和多种 XML 源文件可在结构视图和原文之间切换。完整条目见 [100 项优化与验收清单](docs/1.10迭代设计.md)。

“变更记录 → 管理记录 → 移出普通日志”移除指定事件的公开展示，管理员在“管理已移出记录”验证口令后可找回和恢复。独立的版本、备份和管理审计仍然存在。目录配置可在保存前预演排除规则；目录卡片可查规则沿革。

主窗口 × 收到 Windows 托盘。设置页可查看引擎 PID、线程最近活动、待处理任务；托盘的“退出监控”才会结束本次监控。采集的是已保存到磁盘的稳定内容，编辑器内未保存的草稿不会生成版本。Windows 托盘、后台恢复和实际编辑句柄的验收步骤见本轮清单。

## 1.9.0 复核工作台与记录管理

打开「复核工作台」，可跨文件处理待复核版本，按需登记结论、备注并导出。Excel 整行视图支持旧地址、新地址和编号定位。CSV/TSV 支持按编号或按原始坐标比较。Word、PDF 表单、ODT、ODS、ODP 和动图增加了对应的内容与排版检查。完整清单见 [本轮 100 项及追加需求](docs/1.9迭代设计.md)。

### 更正和撤回日志

在实际仓库首次使用前，由仓库负责人运行 **FileGuard-RecordAdmin.cmd** 初始化本机管理口令，至少 12 个字符。开发环境先按下文安装依赖。也可在项目根目录运行 `python -m engine.main --record-admin`；已打包的引擎可运行 `fileguard-engine.exe --record-admin`。便携版按 portable.flag 定位 Data，指定 FILEGUARD_DATA 的部署需使用同一环境配置。更换口令要输入旧口令。

在「变更记录 → 管理记录」输入口令，可查看原始事件、追加公开更正说明、撤回或恢复展示。每次处置都要填原因。撤回后普通变更列表、首页最近活动和变更导出只保留撤回标记及记录编号、时间。原始事件保持完整，私有原因保存在处置历史中。启用权限后，完整备份也需验证口令。

这项权限保护应用内的记录管理入口。文件版本历史仍可供原来的使用者追溯。能直接读取数据库、备份或共用同一 Windows 账户的人仍可能看到原始数据。需要按人员保密时，请部署独立 Windows 账户和仓库、备份目录的访问权限。

### Windows 后台运行

桌面版已启动后点窗口 × 会隐藏工作台。左键托盘图标可重新打开，右键「退出监控」会停止。桌面外壳独立于界面约每 5 秒检查引擎是否退出，发现异常退出后尝试重启。此行为适用于当前登录会话；注销和关机结束本次会话。「登录 Windows 后后台启动」可在下次登录后恢复。浏览器开发版仍需要保留终端。

在有 Windows 图形桌面的测试会话中，先构建并解压便携包，再运行 `python scripts/check-windows-background.py "完整的便携包目录"`。脚本复制测试程序到临时目录，模拟关闭实际窗口、改文件、结束测试子进程并验证重新记录，随后唤回同一窗口。当前 Linux 环境只执行了独立引擎的无界面采集测试。

### 核查备份

「系统设置 → 核查已有备份」可以在服务运行时核对历史版本与对象。命令行入口为 `python -m engine.main --inspect-backup 备份.zip`。预检不替换当前仓库。新清单的数据库摘要和逐对象摘要用于发现损坏，不能证明备份来自受信任的发送者。

## 1.8.0 先体验整行复核

打开中文界面预览，在首页点击「体验整行对比」。同一条库存记录保留旧、新行号，整行以减号和加号显示，变化的单元格另行着色。可展开未变行、按工作表和列分页，也可切换到「单元格与属性明细」筛选和导出。修订后的文字、PDF 页、幻灯片、CSV 数据行和 ZIP 成员各有对应视图。

日常编辑可保持文件打开。手动保存或自动保存写入本地目录后，监控引擎才有可供采集的新内容。遇到独占或写入竞争时，可在「目录监控 → 等待保存」查看文件名及复查情况。只在内存中的输入和两次扫描之间消失的中间状态无法补录。需要回写历史版本时，请先保存并关闭仍在编辑该文件的窗口。

完整修改和验收方法见 [100 项优化清单](docs/1.8迭代设计.md)。运行离线交互回归使用 `node tests/test-view.cjs docs/中文界面预览.html`，进程协议检查使用 `python scripts/check-engine.py`。

## 先看界面

单独提供的《FileGuard-中文界面预览.html》下载后可直接用 Edge 或 Chrome 打开。示例工作区有 3 个业务目录，包含仓库台账、质量管理和产品资料。点击首页最近变更里的「库存台账.xlsx」，查看新增的 MD-003 整行、C2 数量、D2 格式与 E2 公式。MD-002 从第 3 行移到第 4 行，现存量从 48 改为 52。在「单元格与属性明细」点击「新增」只看新增记录，也可切换「按原始坐标」逐格核对。可以切换版本、搜索、筛选、查看子目录和切换浅色／深色。示例数据仅用于体验，关闭页面后示例设置复位。

在版本对比的「单元格与属性明细」中输入「加粗：是」可直接找到 D2 的格式修改。点击「导出筛选结果」保存 CSV；导出范围覆盖全部匹配页。桌面模式下恢复版本会先检查原路径，遇到新出现的同名文件可在时间线使用「另存」。

在首页的最近变更中选择「检验作业指导书.docx」。默认视图列出三项：新增复核人签名段落、保存份数由 2 份改为 3 份、页脚版次 A 改为 B。点击「按原始位置」可以逐段号复查。审计中心可按管理操作和日期范围筛选，也能直接搜索操作名称。

在「变更记录」搜索旧名「仓库交接」，点「近七天」后能找到改名为「仓库移交记录.md」的事件。可以打开详情，再返回原筛选；也可以按匹配条数导出 CSV。

在「文件管理」切换「全部历史文件」并搜索「交接复核清单」。同一路径有两条独立记录，当前文件是 V1，已删除文件留有 15 个版本。打开已删除记录的时间线，输入 V2 可直接与 V1 比较。

在「目录监控」点「需关注」可定位示例中的「质量管理」，也可从通知中心直接进入。「仓库台账」的上次扫描跳过 3 项，展开可查看临时文件、备份文件及缓存目录的原因。预览中的「模拟扫描」演示队列状态；开发版和桌面版由引擎执行真实扫描。

在首页最近变更中选择「批次收货台账.xlsx」，切换至「单元格与属性明细」，在「差异类别」选择「数据类型」。编号 RK-001 的数量在两版都显示 12，但旧版存为数字，新版存为文本。可点击「交换版本」反向复核，也可导出当前筛选。

## 运行真实监控

### Windows 开发运行

1. 安装 Windows x64 的 Python 3.12。确保 `python3.12`、`py -3.12` 或 `python` 能从命令行启动 Python 3.12。
2. 将源码压缩包完整解压到可写目录。
3. 双击 **启动开发版.cmd**。脚本创建项目内虚拟环境，安装依赖，然后使用本机浏览器打开工作台。首次安装依赖需要网络，已安装后可直接执行 `.venv\Scripts\python.exe scripts\dev.py` 离线启动。
4. 点击「添加目录」，输入本机现有目录的完整路径。首次扫描建立基线，请等「最近扫描」出现时间后编辑文件。
5. 保持终端运行。关闭网页后，开发引擎继续工作；关闭终端即结束。托盘、系统目录选择器和登录启动由打包后的桌面程序提供。

开发服务只绑定 127.0.0.1 上的随机端口，用单次启动随机令牌校验请求。桌面版用进程管道通信。

### Python 开发环境

在项目根目录运行，下列命令使用同一个 Python 3.12 环境。

```sh
python -m pip install -r requirements.txt
python scripts/dev.py
python -m unittest discover -s tests -v
```

`FILEGUARD_DATA` 可指定独立的开发数据目录。版本仓库须与监控根目录互相独立。首次使用可以建立一个空文件夹，保存测试文件，观察变更，再接入日常资料。

## 构建 Windows 桌面版

使用 Windows 10/11 x64 构建机，安装 Visual Studio 2022 Build Tools 的「使用 C++ 的桌面开发」和 Windows SDK、Rust stable x86_64-pc-windows-msvc、Node.js 22.13 或更高版本、Python 3.12 x64。首次构建需联网获取依赖、打包工具和 WebView2 离线安装组件。

在项目根目录双击 **构建Windows版本.cmd**，或运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1
```

脚本顺序执行后端回归、PyInstaller 引擎构建、打包引擎协议检查、TypeScript 检查、界面编译和 Tauri 打包。构建成功后，`release/1.23.0` 下包含中文 NSIS 安装 EXE、MSI 和 `FileGuard-Portable-x64.zip`，并生成 SHA256SUMS.txt 校验清单。便携版需要本机已安装 WebView2，解压完整文件夹后启动 FileGuard.exe。请保留同目录的引擎和 portable.flag。

项目也含手动启动的 Windows CI 工作流，可在 GitHub Actions 生成安装包和便携包。

构建器与离线 WebView2 配置参见 [Tauri Windows Installer](https://v2.tauri.app/distribute/windows-installer/) 和 [Tauri Sidecar](https://v2.tauri.app/develop/sidecar/)。
