# FileGuard 1.9.0 · 100 项优化与验收清单

基线为 1.8.0。以下 100 项均已进入本版源码。另列本轮追加的记录管理权限和 Windows 后台常驻需求。

**先试一遍**　预览中打开「复核工作台」，选择一个版本，登记「需跟进」并填写问题，然后从该状态进入差异对比。在「变更记录」选择「管理记录」可以用虚构数据体验公开更正、撤回和恢复。

## 追加需求 A　有权限的记录更正、撤回与恢复

1. 仓库负责人在本机运行 FileGuard-RecordAdmin.cmd 首次设置管理口令。变更现有口令需要验证旧口令。应用内每次管理操作单独验证，不设置通用口令。
2. 普通界面允许定位「已撤回」标记。管理员可给事件追加公开更正说明，或填写私有理由撤回。普通列表、最近活动和变更 CSV 保留事件编号、时间及撤回标记，去掉文件名、路径、摘要和版本关联。
3. 在「管理记录」输入管理口令，可查看原始事件、历次处置及原因，也可恢复展示。公众审计留下操作和事件编号。冲突写入会要求重新核对。
4. 配置口令后的应用内完整备份也要求管理口令。复核意见、文件历史和版本对比有各自的访问范围。持有仓库数据库、旧备份或 Windows 账户权限的人仍可能读取原始内容。独立 Windows 账户、仓库／备份文件夹权限和磁盘保护需由部署方设置。

## 追加需求 B　Windows 关闭窗口后继续监控

1. Windows 桌面窗口点 × 收到托盘。左键托盘图标打开工作台，右键「退出监控」结束当前登录会话中的监控。登录启动可在系统设置中开启。重新以后台参数启动不会弹出已有窗口。
2. 桌面外壳每 5 秒检查一次引擎是否已退出。即使工作台一直隐藏，也会尝试重新启动；已保存的目录、版本和待处理任务继续沿用。停机期间消失的中间状态无法补录。
3. 独立引擎无界面请求仍能记录变更已在 Linux 进程测试中验证。Windows 托盘、实际窗口关闭及引擎意外退出的实机验收脚本为 scripts/check-windows-background.py。此脚本本次未在 Windows 执行。
