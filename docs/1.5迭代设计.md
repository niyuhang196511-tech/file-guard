# 1.5.0 文件查找与版本定位设计

仓库交接时，复核人可能只知道旧名称，也可能面对一份删除后又按原路径重建的清单。本轮把文件搜索、状态判断与版本定位连成一条可检验的流程。

| 环节 | 设计 | 验收 |
| --- | --- | --- |
| 找到同一份文件 | 文件管理及全局选择器均检索当前相对路径及重命名、移动事件的原相对路径。按文件 ID 返回，每个文件最多出现一次。仅靠历史路径命中时显示最近匹配的原路径。由旧事件打开时间线时，事件详情保留当时路径，时间线标题取文件的最近记录名称。 | 连续改名两次后，输入第一或第二个名称均能打开当前文件的同一条版本链。 |
| 分辨同名记录 | 文件管理默认查看当前监控范围，可切换全部历史、已删除、规则已排除、目录已移除。全局选择器默认全部历史，支持相同范围。根据最近扫描结果显示状态、完整目录及最近版本。暂停目录里的在册文件显示「目录已暂停」。 | 同路径删除再重建可分别找到已删除与当前记录。移除目录保留历史，分组不重复。 |
| 定位指定版本 | 时间线按新到旧每页显示 10 条。可按精确版本号（如 V2 或 2）及本地记录日期交叉筛选，显示匹配数量；查看另一文件时恢复默认条件。比较仍可选择完整版本链，时间线上的比较按钮始终使用真实父版本。 | 15 个版本分为两页，V2 不匹配 V12；无结果可清除条件；V2 可与 V1 比较。 |
| 样例与兼容 | 提供同名历史副本的离线示例。沿用 SQLite 现存文件、版本、事件及索引，原有调用的默认范围保持一致。 | 新旧仓库无需转换。样例与桌面使用相同的筛选规则，真实引擎及中文界面分别验证。 |
