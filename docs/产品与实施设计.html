FileGuard　／　产品设计Windows 桌面应用 · 1.0 开发基线

文件变更监控
与版本追溯系统

从一次文件保存，追溯到具体改动，再安全找回旧版本。

目录递归监控本机业务文件夹，支持独立暂停与排除规则。
内容用工作表、单元格、段落和页码解释变化。
版本保留原件、变更明细与恢复记录，离线查询。

典型操作

仓库人员打开「库存台账.xlsx」的变更记录，看到库存表 C2 从 100 改为 80；质量人员复核前后两个版本，可先另存历史副本，确认后恢复。

定位按文件名、目录、格式、类型或日期查询。从事件查看对应版本，支持任意两个已存版本比较。
比较选择版本，按工作表或位置筛选。显示具体位置、旧值、新值及新增／删除／修改类型；无法解析时保留原件。
恢复另存副本，或确认恢复到原路径。原位恢复先保存现状，验证历史对象，校验写回结果，再追加恢复事件。
审计与备份导出事件，制作仓库备份。记录管理操作；离线还原备份前完整校验，保留现仓库。

数据范围

同一用户账户下离线运行。以稳定可读取的保存状态为版本单位。文件被其他软件独占时等待重试；暂停、停机及连续写入期间的中间状态可能无法重建。

FileGuard　／　技术架构运行与数据边界

桌面外壳、监控引擎、版本仓库

桌面进程

Tauri 2 / Rust 承载 Vue 3 中文界面。托盘可显示窗口、退出应用。关闭窗口隐藏到托盘，后端继续工作。以当前账户权限读取用户选择的目录。

本地引擎

Python 独立进程负责文件观察、定期核对、内容解析与 SQLite。Rust 通过标准输入输出请求业务操作。UI 资源随程序提供，运行时无需互联网。

一致性

流式计算 SHA-256，对照读取前后文件状态，临时对象在同一文件系统提交。对象先落盘，再在一个事务内提交文件、版本、事件和解析任务。

监控与去重

目录变动登记待扫描任务；合并短时间通知，启动后扫描。基线后按路径与文件标识关联；无法唯一确认的移动保守记为删增。内容相同但时间变化时只增元数据事件。

失败与重试

任务保存在数据库。文件读写冲突、解析失败和根目录断开分别记录。解析在独立队列消费，限制输入体积；单个文件的失败不应阻塞其他文件。

存储与访问

数据默认位于用户本地应用数据目录。仓库按摘要前缀分桶，多版本复用同一对象。备份包括一致的数据库快照与引用对象；保留原目录权限边界。

完整性与审计边界

恢复先核验对象哈希。文件系统事件只标注采集来源，操作账号仅用于软件内明确发生的动作。本地管理员具备修改本机数据的能力。

恢复顺序

校验历史对象 → 保存尚未记录的当前文件 → 临时写入 → 核验 → 替换 → 重新读取目标并写入新版本。

备份还原

创建独立备份，包含版本对象和数据库快照。还原在桌面进程关闭后执行，先验证数据，再切换仓库并保留旧库。

分期与限制

首轮以监控、精确差异和可核验恢复为发布核心。后续扩展跨目录移动归并、工作表重命名推断、图像像素对比、加密仓库及共享服务器操作人关联。

实际交付状态以随源码提供的测试报告为准。大规模目录、长时间压力和 Windows 实机安装测试通过后再发布生产版。
