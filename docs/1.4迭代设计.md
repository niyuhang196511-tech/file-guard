# 1.4.0 变更记录追溯设计

## 使用流程

库管员只记得移交前的文件名，希望找到过去一周的改名和移动记录，打开详情复核，再回到刚才那一页，导出交接清单。

| 环节 | 交互和数据规则 | 验收示例 |
| --- | --- | --- |
| 搜索 | 在变更记录中同时匹配事件当时的相对路径和原相对路径。空格去边，路径分隔符接受两种写法。列表及导出共用相同的扩展名规范化规则。 | 搜索旧文件名能找到重命名事件，搜索旧目录能找到移出事件。 |
| 缩小范围 | 将关键词、目录、扩展名、变化类型放在第一行。日期范围和包含建档记录的开关放在第二行。提供今天、近七天，按本机日历包含起止两天。 | 从工作台点击今日变更时，当日两端与排除建档条件可见；日期逆序时清空旧结果并提示。 |
| 复核 | 由变更列表进入历史或对比，显示返回变更记录按钮。返回时恢复筛选和页码；从侧栏主动打开列表时从第一页开始。 | 第二页查看详情，切换时间线与对比后返回，仍处于原筛选的第二页。 |
| 导出 | 显示匹配数量，导出全部匹配项。桌面 CSV 与离线示例均保存事件原路径、新路径、时间与版本。无结果、正在筛选或日期无效时禁用导出。 | 输入大写且不含点号的扩展名、跨页筛选，CSV 行数与匹配数一致。 |

在示例仓库用一次真实改名生成「仓库交接.md → 仓库移交记录.md」事件，保留其他业务样例。沿用现有中文界面配色、分页与暗色主题，不改数据库结构。
